## 1. 项目定位与目标

Mini City 3D 是一个通过浏览器运行的轻量级第三人称 3D 城市游戏原型，目标是逐步形成具有中国上海城市辨识度、可以步行探索、驾驶车辆并与 NPC 互动的卡通城市体验。

项目从早期低多边形城市与驾驶原型，逐步扩展为带有步行人物、车辆上下车、近战/枪械操作、NPC 交互，以及上海外滩和黄浦江场景的可玩原型。

### 核心设计原则

- **浏览器即玩**：静态网页部署，尽量避免安装客户端和复杂构建步骤。
- **第三人称优先**：人物在画面中可见，镜头跟随人物；镜头距离与准星位置要服务于实际操作。
- **上海场景辨识度**：以外滩历史建筑、浦东天际线、黄浦江、拱桥与观光游轮构成主要视觉记忆点。
- **轻量化渲染**：优先保留标志性建筑和必要交互，减少重复建筑、路灯、树木、阴影和无意义细节，控制浏览器渲染成本。
- **功能连续性**：城市美术迭代不能轻易破坏人物、枪械、NPC、车辆、碰撞和任务/战斗交互。

## 2. 技术方案与仓库结构

- 在线地址：https://changfengdaxia0030217.github.io/Mini-City-3D/

## 3. 功能与开发历程

### 阶段 A：可运行的城市驾驶原型（2026-10-11 起）

项目初始目标是先建立可直接在浏览器运行的 3D 城市原型。早期版本包含：

- 低多边形、色彩鲜明的城市、道路与绿地。
- 可驾驶车辆与跟随镜头。
- 基础碰撞、键盘/移动端控制和实时车速显示。
- 将项目公开，并配置 GitHub Pages 自动发布流程。

阶段目标是先打通“打开网页即可玩”的完整路径，再持续迭代城市和玩法，而不是一开始引入复杂工程架构。

### 阶段 B：第三人称人物与基础动作（2026-10-12 起）

在驾驶原型上加入步行人物和人车切换，持续修复人物层级、朝向和操控问题：

- 增加人物模型、第三人称跟随镜头与步行控制。
- 保留车辆驾驶功能，并完善人物上下车流程。
- 调整人物前后方向、面部朝向、转向响应和虚拟摇杆死区。
- 增加 F 键出拳等近战动作；按需求避免出拳后出现干扰操作的文字提示。
- 修复下车后人物模型消失的问题。提交 82ca25e 将备用人物模型独立放入 fallbackAvatar 层级，避免加载动画人物时破坏备用模型层级。
- 规划并逐步加入跑步、持武器、NPC 攻击玩家、人物血条以及 NPC 死亡掉落现金等战斗反馈。

人物控制和镜头被作为整体调校：只改变人物模型外观不能解决转向和瞄准问题，控制器朝向、模型正面方向、相机朝向必须明确分工。

### 阶段 C：鼠标、镜头、准星与战斗操作（2026-10-12 至 2026-10-17）

围绕第三人称射击体验进行多轮调整，重点是让鼠标输入、镜头旋转、准星、射击射线和手持武器方向保持一致。

已进行的改进包括：

- 鼠标视角控制与右键按住观察/瞄准模式。
- 滚轮镜头距离调整；默认第三人称镜头进一步靠近人物，避免人物显得过小。
- 调整步行转向与移动优先级，改善键盘和虚拟摇杆操作。
- 将准星从默认中心调整到屏幕高度约 30%，这是目前确认的目标位置。
- 让射击射线使用与准星相同的屏幕坐标，而不是仍指向画面中心。
- 将 NPC 辅助瞄准的距离计算改为相对准星位置，避免准星移动后辅助瞄准仍以屏幕中心为基准。
- 调整枪械水平朝向与俯仰角，使枪械视觉方向尽量匹配镜头和准星射击方向。
- 射击目标使用射线检测；曳光/射击表现从枪口位置发出。

### 阶段 D：城市风格转向卡通上海（2026-10-15 起）

用户明确提出将城市道路和建筑改为中国上海风格，并指出早期场景缺少可辨识的外滩建筑和黄浦江。此后场景围绕上海地标重做：

- 增强浦东天际线，包含东方明珠、上海中心/金茂等风格化地标。
- 改造外滩历史建筑立面，提升海关大楼等建筑的辨识度。
- 添加中英文地标铭牌，减少相似高楼的重复堆叠。
- 调整道路走向与弯曲河道，让场景布局更接近江岸城市空间。
- 加入黄浦江拱桥和观光游轮/码头元素，强化两岸关系与滨江观光感。
- 将黄浦江水面调为更明亮的蓝色（材质颜色约为 #29a9e8），并关闭水面的阴影投射/接收以减少开销。
- 保留卡通化、简化几何的视觉方向，避免为追求细节而堆叠过多模型。

### 阶段 E：控制场景复杂度与帧渲染开销（2026-10-16 至 2026-10-17）

用户多次强调地图不需要大量建筑，路灯、树木和凳子等装饰也不应过多，否则浏览器运行变慢。因此优化方向不是简单继续增加细节，而是有选择地保留地标。

已实施的优化主题：

- 减少重复的普通建筑和远景天际线细节。
- 复用盒体等几何体，简化外滩立面阴影。
- 减少路灯数量，并关闭部分装饰灯具的阴影。
- 降低远景建筑、石库门装饰、滨江树木和桥梁灯光的细节与阴影开销。
- 复用 NPC 几何体，关闭环境 NPC 的阴影。
- 复用交通车辆几何体，避免普通车辆产生不必要的阴影。
- 仅在交通灯相位变化时更新对应材质，而不是每帧重复设置。
- 浏览器窗口缩放后继续限制渲染分辨率，避免像素成本随高分辨率屏幕无限增长。

### 阶段 F：准星高度与射击逻辑最终对齐（2026-10-17）

准星位置曾在多次迭代中经过屏幕中心、60% 和更高位置的试调，最终需求确定为屏幕高度 30%。需要注意 CSS 位置和 Three.js 射线坐标使用不同坐标体系：

- CSS 的 top:30% 表示从屏幕顶部向下 30%。
- Three.js NDC 的 y 轴方向与屏幕坐标相反，对应值为 y=0.4（以常规 NDC 纵向范围 [-1,1] 计算）。
- 当前射击射线使用 weaponScreenCenter = new THREE.Vector2(0, .40)。
- 辅助瞄准距离相对于同一准星坐标计算。
- 枪械水平朝向同步镜头 yaw，并按准星高度计算俯仰补偿。

### 射击问题的排查顺序

若准星瞄准 NPC 但未命中，不要只移动 CSS 准星。按以下顺序排查：

1. 确认准星 CSS 的实际位置与 weaponScreenCenter 的 NDC 坐标一致。
2. 确认射线检测和辅助瞄准使用同一个屏幕坐标。
3. 确认相机矩阵已更新，再执行投影或射线检测。
4. 检查 NPC 碰撞/命中体是否覆盖可见模型。
5. 检查第三人称相机与枪口存在视差：射线命中点和枪口曳光终点应统一。
6. 检查人物静止时身体朝向、上半身/手臂姿势和枪械方向是否分离。
7. 最后才调整瞄准辅助半径、镜头肩位或枪口位置。

## 6. 重要设计决策

1. **以地标代替数量**：优先保留东方明珠、外滩海关大楼、黄浦江和拱桥等高辨识度元素，避免通过堆叠普通建筑营造规模。
2. **控制阴影成本**：阴影主要用于近景和关键物体，远景装饰、环境车辆、部分 NPC 与水面不需要阴影。
3. **共享几何体**：重复出现的车辆、NPC 或盒体尽量复用 Geometry，避免大量重复创建同构资源。
4. **区分控制器和视觉模型方向**：人物根节点用于移动/碰撞，视觉模型可以有独立朝向补偿，避免模型正面修正破坏移动轴。
5. **准星与射线共用坐标**：准星显示位置、NPC 辅助瞄准和射击射线必须以同一个屏幕坐标为基准。
6. **保留降级路径**：外部动画模型加载失败时，应保留备用人物模型，不应因网络失败而导致角色不可见。
7. **改动后进行回归**：城市与渲染优化必须同时检查人物、车辆、碰撞和战斗，不应只检查截图效果。

## 7. 当前已知风险与待办

按优先级排序：

### P0：射击手感与人物朝向

- 在浏览器实际开枪，验证 30% 高度准星的命中位置与 NPC 受击反馈。
- 验证枪口曳光、射线命中点、武器视觉朝向三者一致。
- 验证人物静止时，躯干、手臂和枪械不会出现明显不同向。
- 检查鼠标上下移动是否符合玩家直觉，确认没有反向控制问题。

### P1：场景辨识度与可玩路线

- 从玩家出生点确认外滩建筑群、浦东地标、黄浦江、拱桥和游轮能形成清楚的视觉关系。
- 验证桥梁是否可通行、碰撞范围是否与可见道路一致。
- 继续减少无意义的路灯、树木、长椅和重复建筑，但不能删掉支撑导航和地标识别的关键物体。

### P1：性能和兼容性

- 在不同分辨率下测量帧率与渲染稳定性，而不只依赖主观感受。
- 检查外部 CDN/模型资源失败时的降级路径。
- 检查 resize、输入焦点、鼠标锁定和触控行为。
- 避免在每帧循环中重复创建几何体、材质或临时对象。

### P2：工程可维护性

- 随着功能稳定，将单文件中的场景创建、输入、人物控制、车辆、NPC/战斗、HUD 分阶段拆分。
- 建立一份简短的手工回归测试记录。
- 对关键数学逻辑（NDC 坐标转换、相机射线、碰撞）添加可重复的验证步骤。
- 重要功能完成后更新本开发文档，并在提交说明中写清变更原因和验证结果。

## 8. 发布与开发工作流

1. 在仓库 main 分支修改代码和文档。
2. 提交前检查 HTML/JavaScript 语法、初始化顺序与相关功能回归。
3. 推送后查看 GitHub Actions 的 Pages 工作流是否成功。
4. 打开在线地址验证真实页面；部署成功不等于所有玩法均已验收。
5. 若浏览器仍显示旧版本，先强制刷新，再检查 Pages 部署提交是否包含最新 commit。
6. 将新增功能、已知问题、测试结果和对应提交链接补充到本文。

## 10. 当前基线声明

截至 2026-10-18，本项目已从基础城市驾驶原型发展为带有上海风格场景、第三人称人物、车辆、NPC 和射击相关逻辑的持续迭代原型。当前优先事项不是继续无差别增加场景细节，而是：

1. 实际验证准星、射线、枪口和人物姿态是否一致；
2. 保证外滩、黄浦江、拱桥与游轮的辨识度和空间关系；
3. 继续以共享资源、减少装饰物和控制阴影为主优化性能；
4. 每次修改后验证人物移动、驾驶、上下车和战斗没有回归。

本文记录的是当前已知实现与测试计划；未经真实浏览器验证的内容明确标记为待验证，不应视为已经通过验收。
